## 2.1.0 — 2026-10-23（发布评审修复轮：判定语义、鉴权、安装态、门禁可观测性）

**⚠️ 升级前必读**：本版**修正了「达标」结论行与报告披露**，并把手动「建议」升级为**拒绝启动**。
行为变化集中在部署与安装两个面；评分口径本身未变（`PASS_THRESHOLD=8.0`，短板容忍带 1.0
本版第一次被写成显式常量 `PASS_SHORTFALL_TOLERANCE` 并在代码/文档/报告四处同口径）。

### 行为变化（可能影响你现有部署）

| 变化 | 影响 |
|---|---|
| **鉴权 fail-closed**：`--host` 非回环且未设 token 时**拒绝启动**（退出码 2） | `run_server.py`/`run.py panel` 需 `PM_API_TOKEN`；`run_modelhub.py` 需 `PMH_GATEWAY_TOKEN`。Docker 默认 `--host 0.0.0.0`，**容器现在必须带 `PM_API_TOKEN`** 才起得来（示例命令已更新） |
| **报告结论行按真实原因分支** | 「均分过线但短板/断言卡住」不再印成「均分 X < 阈值」，改为点名挡路的闸（最低分/保守下界/断言一票否决/用例数不足） |
| **报告新增两条披露** | 假后端演示轮在头部注明「不是真实评测读数」；memory 命中历史资产时注明「优化参考」 |
| **评分总览新增协议行** | 本轮分数的评分协议（印象式／判定式）与**同轮混用**情况直接印出 |
| **REST `/api/optimize`、`/api/race` 新增 422 预检** | `contains/exact` 模式下 expected 写成需求规则时当场拒绝（与 CLI 同一判据），不再静默降级成「仅提醒」 |
| **`pip install .` 安装态修复** | 面板/桌面/MCP/历史的子进程转发退到 `python -m pm.cli.console`；`case_templates/` 随包安装；产物目录落 `<cwd>/logs`；补齐 PyPI 元数据（license/authors/readme/urls/classifiers） |

### 修复

- 报告结论句事实错误（实测印出过「均分 8.5 < 阈值 8.0」）；下界过线时也会印「也没过线」。
- 成对盲评：单向调用失败不再被归因成「位置偏置」（记 skip，「覆盖不足」行如实说）。
- 预算耗尽分支漏记 `llm_calls`（optimize/revise 两处），成本台账偏低。
- 评估缓存命中后 `sample_index` 恒为 0（溯源字段错）。
- 修订版本注记在带净增量时永不闭合括号。
- 覆盖率分项线 82 → 93（此前实测 98.35%，留 17 点余量＝这条线没接）；CI 的 `-qq` 吞掉 passed/skipped 汇总行已修，终端汇总新增跳过数与原因聚合。
- 文档：evaluation.md 的 κ 裁决（「与瞎猜不可区分」按轮归属，新增 2026-10-23 裁决段）、英文 README 地板纳入断言、样例报告重生成（四处自相矛盾）。

### 已知边界（不变）

- 尺子仍未对准：活账本 1 轮 / 11 锚点、其中 6 条人工分是编造的；**达标 ≠ 验收依据**。
- 安全豁免 W7/W8/W9 仍是书面豁免（本版只做了主产品与网关的 fail-closed，未收回三服务豁免）。

## 1.1.0 — 2026-09-19（提示词重建 + 测量层加固）

**⚠️ 升级前必读：本版本改变的是"分数怎么产生"，不是"分数怎么显示"。**
从这一版起，`avg_score` / `min_score` / `ci_lower` / `Δ` 与 1.0.0 的历史运行**不可比**；
把旧报告与新报告放在同一张表里比较，得到的结论无效。已有告警/看板若引用过阈值 8.0 的
历史均值，请按下面"迁移步骤"重新基线一次。

### 破坏性变化（对数据，不对 API）

| 变化 | 影响 |
|---|---|
| 测试用例只由需求生成，mockgen 不再看候选提示词 | 旧口径下基线臂被"考卷由考生出题"污染性打低，Δ 普遍虚高；新口径的 Δ 通常会更小也更真 |
| 评分锚点重构：编造/无依据关键事实从 5-6 档下移到 3-4 档，并加"含编造则加权分封顶 6.0" | 同一份有编造的输出，分数会明显低于 1.0.0；这是修正，不是回退 |
| 成对盲评改双向评（正序 + 交换 A/B），两序不一致记 tie | `pairwise.verdict` 更容易是 tie/持平；`position_flips` 是新字段，非 0 就说明单序结论曾被座位决定 |
| 注入存活按**用例**计数（1.0.0 按样本，1 条用例会报成 2 条）；种子用例的校验码改由代码派生；判定从「标记有没有出现」改成「以什么姿态出现」（拒绝时复述载荷不再算被劫持） | `injection_survival.total` 语义变化；旧报告里的数字要除以采样次数理解。模板自带的高频词 marker（如「已解决」）不再作为定罪依据 |
| 评估缓存键加入 `rubric=<sha1(评分提示词)>` | 升级后评估缓存**一次性全失效**（预期行为）；目标输出缓存仍命中 |
| 新增报告字段：`judge_health`（评委同源检测）、`revision_delta`（fixed–broken 记账）、`baseline_injection_survival` | 只增字段，不改判定 |
| 新增「本轮 Δ 不可采信」硬提示 | 本臂存在"零有效样本"的用例（目标模型空输出/调用失败）时，Δ 表下方直接给结论不可用 |
| 新增 `PM_JUDGE_JITTER`（评委复现性极差，由 `calibrate --repeat 3` 量出）：**填了它**，`ci_lower` 改用"目标采样噪声 ⊕ 评委抖动"的合成带，仲裁触发线抬到 `max(配置值, 2√2·jitter/1.693)` | 填了它的运行与没填的**不可比**（下界更低、仲裁更少）。默认 0.0 时逐字等于 1.1.0 的行为，但请别拿填前填后的两张表并排比较 |
| 锚点集 6 → 11 条（新增 5 条取自真实跑批的长输出）；校准账本除 `model`/`rubric` 外再记 `anchors` 指纹，并按 `n` 拦换考卷 | 自己做过校准的用户：旧 6 条基线与新 11 条读数**不可比**，账本会明说"锚点条数不同"并另立基线，不会把它当成评委漂移 |
| 仲裁触发线的抖动改按**座位**取数：新增 `PM_EVALUATOR_JITTER` / `PM_EVALUATOR_B_JITTER` / `PM_ARBITER_JITTER`（未填沿用全局 `PM_JUDGE_JITTER`），公式从 `2√2·j/1.693` 一般化为 `2·√(sdA²+sdB²)/1.693` | 只填全局值时算式逐字不变（两位同抖动 ⇒ hypot 就是 √2·j）。填了按座位的数之后，报告那一行会点名它用的是哪两个极差 |
| **评分提示词又长 26%**（`EVALUATOR_SYSTEM` 3846 → 4831 字符，实测）：补"核心交付物缺位"这一类锚（三家不同谱系的评委在同两条锚点上同向偏 +2.25~+3.53，人工只给 6.0/7.0） | 评委提示词是主要 token 成本，且 ×评委数 ×用例数 ×采样数 —— 默认档一轮的判定 token 大约多两成。`rubric_stamp` 随之变化 ⇒ **评估缓存一次性全失效**（预期），且 1.1.0 之前的 MAE/偏差全部作废，需重跑 `run.py calibrate` 三角色重立基线。**验证结果（评委 A，11 锚点重基线）**：目标锚 `real-triage-overconservative` 从 Δ+2.80 收到 **Δ+0.35**（移动量 3.5× A 的自我极差 ⇒ 不是手抖），护栏侧三家都没误伤"正确拒答"；但同类的 `real-sales-derived-stats` 仍 Δ+1.85、未触发 7.0 封顶 —— **只治住第一形**。⚠️ 该轮 A 有 1 条锚因 reasoning 耗尽预算被 SKIP（n=11→10），所以 MAE 0.90→0.45 是**换了考卷**的前后测，不能并排引用 |

### 判定线语义澄清

1.0.0 的提示词说"9-10 才是生产可用"，代码却按 ≥8.0 判 —— 同一份 system 里三种口径。
现在统一到：**加权分 ≥ 8.0 = 生产可用**（`PASS_THRESHOLD` 可调），7-7.9 是"均分达标时
单条用例的容忍下限"，不是可用档。评委的自报分与代码加权分的平均偏差仍只用于监控放水。

> ⚠️ **2026-10-23 注**：上面这句里的「生产可用」是 1.1.0 当时的措辞，**现已废止**——
> 达标只代表「过了判定线」，不是效果验收依据（见 README「它给的分，能信多少」与
> `docs/evaluation.md` §三十四）。判定线数值（8.0）与容忍带语义（阈值 − 1.0）未变；
> 2.1.0 起容忍带被写成显式常量 `PASS_SHORTFALL_TOLERANCE`，代码/文档/报告四处同口径。

### 部署配置要求（重要）

思考型模型把 **reasoning 计入 max_tokens**，两处预算在本轮实测中制造了"不抛异常的空返回"：

```bash
# 判定类角色（评委 B 用 glm-5.2 这类推理模型时）
PM_EVALUATOR_B_MAX_TOKENS=24000
PM_ARBITER_MAX_TOKENS=24000
PM_COMPARATOR_MAX_TOKENS=24000
# 目标模型：交付物长度已到数千字符，8000 会在长 prompt 下被推理吃满
PM_TARGET_MAX_TOKENS=16000
```

评委请给 B 配**不同模型家族**（同一网关代理多家族即可，如 sensenova / glm / deepseek）；
只设全局 `PM_BASE_URL` 不够——`.env` 里任何一条 `PM_<ROLE>_BASE_URL` 都会注回来，
`run.py --preflight` 现在探测 9 个角色（含仲裁评委），跑批前请先全绿。

### 迁移步骤（想继续用这套数字做判断的话）

1. 清掉旧告警里引用的历史均值（或标注"1.0.0 口径"）；
2. 用自己的真实需求跑 `--cases-file`（带 ground-truth 的确定性断言）至少 2 个任务域；
3. `run.py calibrate` + `run.py calibrate --judge evaluator_b` 把当前评委的 MAE/偏差入账，
   之后每次改评分提示词都能靠账本的口径指纹分辨"评委漂了"还是"尺子变了"；
4. 生产口径建议 `--samples 3` 起步：本轮实测 `samples=2` 时采样噪声（平均极差 2.19）大于判定余量。

### 新增能力

- **取证先于打分**：`EvaluationResult` 字段序即生成序，评委必须先产出带原文证据的 `issues`
  再打维度分（1.0.0 的 schema 让"先取证后打分"只停留在那句提示词里）。
- **逐条得失账 fixed–broken**：每轮报告并排给出"修好哪几条 / 弄坏哪几条"，均分看不出的
  "修 4 坏 3" 从此可见；修订器同步收到这份账，被弄坏的用例要求先恢复再加约束。
- **对比切片 + 高方差用例优先**：把"最好的通过用例"与"最差的失败用例"并排喂给修订器，
  引导它定位输入差异而不是无脑加全局约束。
- **质量门加硬**：约束段名同义词（改名 `[规则]` 不能绕过 ≤8 预算）、修订净增量代码核对、
  元话语特征句与模板互锁（改模板忘同步 marker 会红）。
- **评委输出形状容错**：对象数组 issues、JSON 字符串、缺尾键、null 数组、**键名同义改写**
  （`quality` 被按它的 description「质量与深度」吐成 `quality_depth`）都不该作废整条评估。
  最后一条是 2026-09-18 真端点跑批里抓到的：一次同义替换让仲裁那一轮重试了一次
  （94 秒、含 429 退避），而 schema 的措辞本身就是那个键名的来源。
  同一族的第三种形态也修了：维度值被写成 `{"score": 3, "reasoning": "…"}`（真跑 10 次），
  而那恰恰是评分提示词要求的"逐维先取证"。
- **新增一轴测量：评委的复现性**（`run.py calibrate --repeat N`）。bias/MAE/r 都是"与人工比"，
  量不到"同一输入给不给得出同一个分"——而双评委分差阈值、仲裁触发率、Δ 的分辨率全隐含这个假设。
  实测（真端点、绕开评估缓存、同输入 3 次）：评委 A 极差 0.25~0.70、评委 B 1.30~2.60、
  仲裁最高 4.43；**`temperature=0` 不改善**，median-of-3 只改善 16% 且个别反而更差——
  机制是"每次选中一套口径"的双峰。读数进漂移账本（`rep_*`），越过 `PM_JUDGE_DISAGREEMENT`
  即印「抖动已淹没阈值」。
- **报告新增三行自我拆台的披露**（都是告警不否决）：`N/M 例出自仲裁者一人`（那不是一个共识）、
  `N/M 条自报分与代码加权分完全相等`（实测评委 A 80%、仲裁 88% —— 这台放水探测器对他们近似恒零，
  因为提示词给了权重、演算示例示范怎么求和，字段又排在维度分之后）、以及两类**满分声明**
  （五维全 ≥9.5 却仍列出问题 = 自相矛盾；五维全 ≥9.5 且 issues 为空 = 无可指摘的强声明，
  实测占 9.4%，而人工锚点最高只到 8.7）。
- **真实调用探针**：`scripts/live_prompt_audit_20260918.py`（T1-T6，代码侧判定，
  含"塞入编造数字必须掉分、掏空内容必须落到不可用档"的反事实敏感度与"候选自带豁免规则
  时评委不能认账"的红队用例）。
