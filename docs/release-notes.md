# Release notes

## 1.1.0 — 2026-09-19（提示词重建 + 测量层加固）

**⚠️ 升级前必读：本版本改变的是"分数怎么产生"，不是"分数怎么显示"。**
从这一版起，`avg_score` / `min_score` / `ci_lower` / `Δ` 与 1.0.0 的历史运行**不可比**；
把旧报告与新报告放在同一张表里比较，得到的结论无效。已有告警/看板若引用过阈值 8.0 的
历史均值，请按下面"迁移步骤"重新基线一次。

### 破坏性变化（对数据，不对 API）

| 变化 | 影响 |
|---|---|
| 测试用例只由需求生成，mockgen 不再看候选提示词 | 旧口径下基线臂被"考卷由考生出题"污染性打低，Δ 普遍虚高；新口径的 Δ 通常会更小也更真 |
| 评分锚点重构：编造/无依据关键事实从 5-6 档下移到 3-4 档，并加"含编造则加权分封顶 6.0" | 同一份有编造的输出，分数会明显低于 1.0.0；这是修正，不是回退 |
| 成对盲评改双向评（正序 + 交换 A/B），两序不一致记 tie | `pairwise.verdict` 更容易是 tie/持平；`position_flips` 是新字段，非 0 就说明单序结论曾被座位决定 |
| 注入存活按**用例**计数（1.0.0 按样本，1 条用例会报成 2 条）；种子用例的校验码也改由代码派生 | `injection_survival.total` 语义变化；旧报告里的数字要除以采样次数理解。模板自带的高频词 marker（如「已解决」）不再作为定罪依据 |
| 评估缓存键加入 `rubric=<sha1(评分提示词)>` | 升级后评估缓存**一次性全失效**（预期行为）；目标输出缓存仍命中 |
| 新增报告字段：`judge_health`（评委同源检测）、`revision_delta`（fixed–broken 记账）、`baseline_injection_survival` | 只增字段，不改判定 |
| 新增「本轮 Δ 不可采信」硬提示 | 本臂存在"零有效样本"的用例（目标模型空输出/调用失败）时，Δ 表下方直接给结论不可用 |
| 锚点集 6 → 11 条（新增 5 条取自真实跑批的长输出）；校准账本除 `model`/`rubric` 外再记 `anchors` 指纹，并按 `n` 拦换考卷 | 自己做过校准的用户：旧 6 条基线与新 11 条读数**不可比**，账本会明说"锚点条数不同"并另立基线，不会把它当成评委漂移 |

### 判定线语义澄清

1.0.0 的提示词说"9-10 才是生产可用"，代码却按 ≥8.0 判 —— 同一份 system 里三种口径。
现在统一到：**加权分 ≥ 8.0 = 生产可用**（`PASS_THRESHOLD` 可调），7-7.9 是"均分达标时
单条用例的容忍下限"，不是可用档。评委的自报分与代码加权分的平均偏差仍只用于监控放水。

### 部署配置要求（重要）

思考型模型把 **reasoning 计入 max_tokens**，两处预算在本轮实测中制造了"不抛异常的空返回"：

```bash
# 判定类角色（评委 B 用 glm-5.2 这类推理模型时）
PM_EVALUATOR_B_MAX_TOKENS=24000
PM_ARBITER_MAX_TOKENS=24000
PM_COMPARATOR_MAX_TOKENS=24000
# 目标模型：交付物长度已到数千字符，8000 会在长 prompt 下被推理吃满
PM_TARGET_MAX_TOKENS=16000
```

评委请给 B 配**不同模型家族**（同一网关代理多家族即可，如 sensenova / glm / deepseek）；
只设全局 `PM_BASE_URL` 不够——`.env` 里任何一条 `PM_<ROLE>_BASE_URL` 都会注回来，
`run.py --preflight` 现在探测 9 个角色（含仲裁评委），跑批前请先全绿。

### 迁移步骤（想继续用这套数字做判断的话）

1. 清掉旧告警里引用的历史均值（或标注"1.0.0 口径"）；
2. 用自己的真实需求跑 `--cases-file`（带 ground-truth 的确定性断言）至少 2 个任务域；
3. `run.py calibrate` + `run.py calibrate --judge evaluator_b` 把当前评委的 MAE/偏差入账，
   之后每次改评分提示词都能靠账本的口径指纹分辨"评委漂了"还是"尺子变了"；
4. 生产口径建议 `--samples 3` 起步：本轮实测 `samples=2` 时采样噪声（平均极差 2.19）大于判定余量。

### 新增能力

- **取证先于打分**：`EvaluationResult` 字段序即生成序，评委必须先产出带原文证据的 `issues`
  再打维度分（1.0.0 的 schema 让"先取证后打分"只停留在那句提示词里）。
- **逐条得失账 fixed–broken**：每轮报告并排给出"修好哪几条 / 弄坏哪几条"，均分看不出的
  "修 4 坏 3" 从此可见；修订器同步收到这份账，被弄坏的用例要求先恢复再加约束。
- **对比切片 + 高方差用例优先**：把"最好的通过用例"与"最差的失败用例"并排喂给修订器，
  引导它定位输入差异而不是无脑加全局约束。
- **质量门加硬**：约束段名同义词（改名 `[规则]` 不能绕过 ≤8 预算）、修订净增量代码核对、
  元话语特征句与模板互锁（改模板忘同步 marker 会红）。
- **评委输出形状容错**：对象数组 issues、JSON 字符串、缺尾键、null 数组、**键名同义改写**
  （`quality` 被按它的 description「质量与深度」吐成 `quality_depth`）都不该作废整条评估。
  最后一条是 2026-09-18 真端点跑批里抓到的：一次同义替换让仲裁那一轮重试了一次
  （94 秒、含 429 退避），而 schema 的措辞本身就是那个键名的来源。
- **真实调用探针**：`scripts/live_prompt_audit_20260918.py`（T1-T6，代码侧判定，
  含"塞入编造数字必须掉分、掏空内容必须落到不可用档"的反事实敏感度与"候选自带豁免规则
  时评委不能认账"的红队用例）。

### 本版验证

`pytest 658 项全绿` / `ruff` / `mypy --strict` / `run.py --selftest` /
`eval_prompts.py`（节点提示词结构契约 6/6）/ 三通道桩 e2e 3/3 /
评委校准：`samples.json` 已从 6 条手写锚点扩到 11 条（新增 5 条取自真实跑批的长输出）并**三个判定角色全部入账**
——扩集后 MAE 评委 A **0.90**（偏差 +0.41，r 0.925）、评委 B **0.98**（+0.53，0.877）、仲裁 **0.97**（+0.62，0.879）；

[evaluation.md](evaluation.md) 第八节。**三家 flag 的是同两条锚点**（偏松 +2.25~+3.53，
