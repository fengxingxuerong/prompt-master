03编码健壮性（本轮发现的真实缺陷）

D-L1（S3 已修复）：不带 charset 的 JSON 请求体中文被按 Latin-1 字节序列写入台账，产生 mojibake（"????"）。根因：部分客户端（如 PowerShell Invoke-RestMethod）序列化行为非 UTF-8。修复：FastAPI 中间件统一拦截 POST/PATCH JSON 体，对可无损往返的 mojibake 执行 latin-1→utf-8 重解码，无法修复的原样透传（不掩盖）。

表 3-1　修复后回归（verify_dl1_v4.py 实测输出）
用例结果证据
坏客户端（latin-1 mojibake body）POSTPASSHTTP 200，LOB-…-F92C
坏客户端 PATCH 中文 notePASShistory note="冷链延误赔付演示"（已还原）

浏览器表单与台账页前端走 fetch+JSON.stringify（恒 UTF-8），本缺陷仅影响脚本类客户端；中间件保证任意客户端落库一致。
