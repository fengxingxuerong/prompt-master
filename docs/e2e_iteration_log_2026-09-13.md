### 发现的问题

| 编号 | 现象 | 证据 |
|---|---|---|
| 判据 1 修复 ✅ | 断言全通过（上一轮 case#0「华东」失败） | `run_55d140dfc027` 事实断言表 |
| 判据 3 修复 ✅ | 无边界过度泛化（上一轮 2 例） | 自动检测 0 例 |
| 判据 4b 修复 ✅ | 交付物写明「已有数据照常输出，只对缺失字段标注」 | 提示词边界段 |
| **R1-a（新）** | **均分反而下降**：8.67 → 7.71，下界 6.63，仍未达标；Δ 仅 +0.17 且盲评 0:4 | 轮次报告 |
| **R1-b（新）** | **约束超载 12 条**，评委点名「模型漏执行」：constraint_compliance 8.38→**7.0**、task_completion 9.25→**7.75** | 维度对比 + 评委问题清单 |
| **R1-c（新）** | **抑制型规则**「停止处理」「不输出任何结论」「仅输出固定 token」→ robustness 8.75→**7.88**，且与"边界仍要作答"的骨架冲突 | 提示词边界段 + 维度对比 |
| **R1-d（新）** | **规则不可判定**：「异常」无阈值定义 + 约束 1/11 语义冲突 → 模型把「45 万低于 120 万」同时判成异常点和"无异常波动特征" | 评委问题清单（自相矛盾条） |

**根因**：互斥边界纪律 + 边界显式化纪律叠加后，修订器倾向"再加规则"来满足反馈，
交付物从 3 条约束膨胀到 12 条、边界分支 6 条 —— **正确性上去了，可执行性下来了**。

### 所做的修改（第 2 轮前）

| 改动 | 落点 | 理由 |
|---|---|---|
| 约束预算 10 → **8**，hint 改成"删到 8 条以内 + 边界规则 ≤4 条" | `pm/quality.py` | 12 条被评委点名漏执行 |
| 新增 `suppressive_rule` 闸（停止处理 / 不输出任何结论 / 仅输出固定 token / 拒绝回答） | `pm/quality.py` | R1-c 的直接诱因 |
| 硬性规则 4/6 重写：约束 ≤8、每条必须**可机械判定**（禁未给阈值的「异常/显著/重要」）、**禁抑制型条款** | `pm/prompts.py`（OPTIMIZER） | R1-b/R1-c/R1-d |
| 修订器新增：反馈出现「约束超载」时**只许减不许加**；出现「自相矛盾」时清理未给阈值的形容词 | `pm/prompts.py`（REVISER） | 阻断"越修越长" |
| 新增 `examples/e2e_round_report.py`（判据自动核对）+ `tests/test_round_report.py`（6 例）+ 3 例新闸测试 | 新增 | 让每轮结论可复现、防工具自欺 |
