# CHANGELOG v1.5.0（2026-10-22）

主题：**从单点 CLI 到多入口 + 测量层诚实化**。本版把"提示词优化闭环"从一条命令行扩成**可进用户 CI 的门禁与多种入口**（原稿改进模式、`check` 体检、`diff --base-ref` 增量门禁、成本预估、插件面板、原生桌面端、MCP 工具），同期把评估/校准这一层"没观测到的都如实标出来"（空产出封顶与告警、评委席降级披露、废样本判据、判别力审计、跨轮聚合分代），工程侧完成三个超千行单文件拆包、桌面窗口移出主包，测试基线 **890 → 1893**。

共 **133 提交**（42 fix / 30 feat / 19 docs / 9 test / 6 chore / 5 refactor / 2 perf）。

## 变更清单

### 1. 产品面：多入口 + 可进用户 CI（本版最大的一块）

- **原稿改进模式 + `check` 零调用体检**（8edcfb7）：补上竞品第一用法"改我已有的提示词"；
  `--prompt/--prompt-file` 让基线臂换成你的原稿，报告 Δ 读作"比你自己的版本好多少"。
- **竞品驱动五件套**（eda2b9c）：差分 / 门禁 / 成本预估 / 出处披露 / 墙钟预算 + 测试与文档同步。
- **`diff --base-ref`**（bffc785）：左侧基线直接取自 git 历史，退出码仍是"有新引入才 1"；
  新文件 / 坏 ref / 参数写错一律退 2 并给人话。
- **`--version`**（bffc785）：主 CLI / `python -m pm.cli.console` / `run_server.py` 三入口，
  值取 `pm.__version__`（唯一事实源）。
- **`check --cases-file`**（6dc5f46）：花钱之前先量考卷"有几票真能否决"。
- **插件面板 `run.py panel`**（d3ca462）：体检 / 考卷 / 两版差分三张零调用卡能点开。
- **原生桌面端 `run.py desktop`**（d4fdcb9 → a2c86b3 → 8d02567 → 4f44534）：Tkinter 窗口演进为
  **"项目对话"**——选项目文件夹 + 写目标 → 只读扫描代码与 Git 进度 → 一次模型分析 → 可复制的提示词；
  无 Key 也能"只读取项目"，不修改用户项目。
- **MCP `cases_check` 工具**（7b5bfc8）："几个工具"这个数改成从真实注册表现算。
- **Key 闸门认多 Key 池与角色级 Key**（bffc785）：修掉"把 `.env.example` 推荐的 `PM_API_KEYS`
  判成没 Key"的假拦，以及"只配 target 一个角色 Key 却放行到晚失败"。

### 2. 测量层诚实化：没观测到的都标出来

- **空产出封顶**：空壳/纯拒答产出总分封顶 6.0 → 4.0（a53a75d / ba73478 / 04d51bb），并披露
  （a5d9bbf）、给高分告警（f4375c6）；修「数据缺失」被误封（abdda8d）、修接线三处对不上
  （1df7be9，TDD 先红后绿）。
- **废样本判据**：从"只认『空输出』一个字面量"扩到**超时**（0c2c2fc）与 **429 限流**（6bae213）两类。
- **报告披露**：评委席降级（b88d1ee）、失败 / 重试（44892c5）、「成功但空」（ed557ac）、校准披露行。
- **记账**：失败的调用此前在台账上**不存在** ⇒ 单列 `failed_calls` / `failed_latency_ms` /
  `retry_requests`（3e683f6）。
- **评委**：席位劣化是**模型**不是端点（d669e7a，两个评委走同一个 base_url）；判别力审计 +
  可估性门槛（f46d75e）。
- **校准**：人工锚点 9 → 22 → 34 → 48 条全确认（e5f2514 / c965c41 / ef12d45 / 8af8c3b）；
  跨轮聚合（b331760）；考卷身份 = 锚点指纹不是条数（3b57583）；漂移崩轮修复（3cb95ef）。
- **history**：按评委尺子身份分代；崩臂不再被静默删掉（b3576ae / 2d365a7）。
- **DNS 预算**：`socket.getaddrinfo` 在 timeout 之前 ⇒ 一次 DNS 挂起让墙钟预算形同虚设
  （实测声明 300s、实返 1800s）；有界预解析落地（aa1e73a）。

### 3. 可靠性：跨进程与鉴权

- **台账耐久**：日聚合跨进程写坏（e60ad97）、静默丢账改从台账重建（6bbd0b2）、
  删掉从未被任何代码读过的"保留上限"承诺（9a99fdb，删承诺而不是补实现）。
- **告警留痕**必须受 `PM_LOG_DIR` 管住（ffbe11e）——假告警此前正灌进运维证据流。
- **读端点纳入 token 保护**（history/status/report/race*）+ 3 处比较改常量时间 + MCP 转发自愈
  （3b3612c）。
- **`retry_after` 不再因浮点抵消超过一个窗口**（28177a9，CI windows 那次独红的真因）。
- **优化器预算耗尽**有原稿就交付、不再一律判 failed（d57d63b / f8d899f）。
