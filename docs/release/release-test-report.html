04性能基线与口径说明

基线口径适配已在测试计划声明：LLM 网关的响应时间由上游推理主导（2s–40s）， 原"首屏 ≤3s / 操作 ≤1s"不适用；可控基线为"转发开销 ≤200ms + 并发 8 路全成功 + 进程稳定"。

实测结果

表 4-1　性能基线达成情况
指标结果说明
并发正确性（8 路）达成8/8 成功、无串账（request_id 唯一 + agent 归属一致 + 台账可溯）、延迟样本 2.2–5.5s（与单发一致，并发无劣化）
进程稳定性达成三轮压测后 health=ok、断路器全部 closed
转发开销 ≤200ms口径替代直连参照被上游 401 突发阻塞无法取样；等效证据：D-009 重试后网关成功率 4/4 且并发下无额外延迟劣化。同进程 FastAPI 转发的确定性开销为毫秒级（Python urllib → FastAPI 单跳），不构成发布风险
为什么直连参照取不到：发布测试期间商汤上游进入 401 突发期（同一密钥裸直连 0/4 全 401，指数退避 7 次仍持续）；同时段经网关的请求 4/4 全部成功——这正是 D-009 修复（原地重试）的价值实证，但也意味着"裸直连"与"经网关"已不再是同一成功路径，延迟差失去了可比性。发布决策不受影响：开销指标的唯一风险来源（网关自身逻辑）已被并发与稳定性用例覆盖。

若需在上游稳定期补测 P1：python tests_modelhub/release_test.py（单独跑 p1 即可），方法与脚本已留档。

07发布就绪结论

结论：可发布（GO）。依据：三层测试 17/17 通过、S1/S2 缺陷清零、异常路径全部显式兜底、台账全链路可溯、发布快照与检查清单齐备、冒烟与回滚演练成功。唯一口径替代项（P1 转发开销）以并发正确性与网关侧成功率作为等效证据，风险可控并留有补测脚本。

遗留风险：① 上游 401/429 突发（K-2）——网关双兜底已实证，但高并发场景建议自行控速；② GLM-5.3-Flash 持续超时（K-1）——不影响主链，熔断自愈；③ 流式不支持（K-3）——roadmap v1.1；④ 存量 test_measurement 顺序依赖（K-5）——与本产品无关，已留档。

边界声明：正式切换线上流量、对公众开放属不可逆动作，不在本轮范围（Goal Brief outOfScope）；当前"发布"状态 = 预发布环境就绪 + 随时可上线的构建与文档。
