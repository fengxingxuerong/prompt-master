# 规则层可靠性表：`check` / `gate` 的确定性规则在版本化语料上的读数

> 对应优化台账 **PE-5**（Round 49，2026-10-29）。竞品依据：AI-Infra-Guard `aig-skill-scan`
> 公开 F1/精确率/召回/FPR、hol-guard `plugin-scanner` 公开信任分权重与基线——本仓此前只对
> **评委**做过这件事（`docs/evaluation.md` §三十一），对自己这层规则从没做过。
> 复测命令：`python scripts/measure_rule_reliability.py`（零调用、零出网、确定性）。

## 一、量的是什么、不量什么

- **量**：`check_prompt_quality` 的 7 条确定性规则（`meta_leak` / `context_leak` /
  `blanket_missing_branch` / `delimiter_unbalanced` / `too_short` / `constraint_overload` /
  `suppressive_rule`）与 `diff_prompts` 的 `regressed` 判决（`gate` 同源）在语料上的混淆计数。
- **判据同源**：测量直接调 `pm.quality` / `pm.promptdiff`，与 `check`/`diff`/`gate` 用同一把尺子，
  不另写一套。
- **不量**：评委判别力（§三十一 那本账）；`--cases-file` 的结构统计（那是计数不是分类器，
  有自己的守卫）；注入装束对公开分类学的覆盖（PE-6 另表）。
- **label 语义**：「这条文本是否真有该类缺陷」的人工判定，**独立于实现**。
  实现命中而 label 为假 = 误报（FP）；label 为真而未命中 = 漏判（FN）。

## 二、语料（`rule_reliability/rule_corpus.json`，入库版本化）

- **真实文本 72 条**：`logs/run_*.json`（1527 份 run）的 `prompt` + `seed_prompt` 全量去重，
  按长度升序编号 R00–R71，**无一挑选**。`logs/` 不入库 ⇒ 语料 JSON 即源，每条带 runs 数与示例 run 号。
- **对抗变体 29 条**：`pm/quality.py` 注释里记过的每类边界各钉至少一条——去空格强特征、
  弱特征组合、否定语境、引用剥离、跨行/同行撇号、行边界启发式、英文段名、裸冒号段头、
  全角括号/圈号编号、逐字段豁免、空输入分支、恰好 8 条的边界、too_short 的 99/100 字符边界。
- **前后对 10 组**：code 通道、命中项增量通道、fixed 通道、identical、措辞层不触发、
  已知盲区（P08）各有着落。

## 四、这张表指出的三件事

1. **`delimiter_unbalanced` 精确率 0.500 —— 两例真实误报（R38 / R42），本轮最大发现。**
   形态：示例行里「行中开标签 + 行尾闭标签」（如 `输入：<客户对话>…</客户对话>`）。
   `_structural_tags` 的行边界判据只认行首/行尾 ⇒ 闭标签被计入结构、配对的开标签没有，
   于是报「没有对应的开标签」。而文本里标签成对、语义无歧义，按缺陷定义记误报。
   对真实交付物的 delimiter 命中**三里两假**。修法方向（未实施，属行为变更需另立轮次）：
   配对时不要求行边，或让「行尾闭标签」先与同行行中开标签配对。
2. **`suppressive_rule` 召回 0.667 —— 一例已知漏判（C14，计 FN）。**
   同一行内的两个英文撇号（`Don't … user's`）会把中间的抑制句当「引用」吞掉。
   2026-10-31 只修了跨行（`[^'\n]`），同行吞并是当时刻意保留的行为——现在它被语料钉住、
   计进召回，不再只是注释里的一句话。
3. **gate 合同符合 10/10，但 P08 钉住一个已知盲区。**
   已命中 code 内的计数增长（约束 10→12 条）对 `regressed` 判决不可见（结构通道可见 +2，
   门禁不行动）。按当前文档合同这是「正确行为」，但读者应当知道：**gate 绿不蕴含约束数没涨**。

## 五、变体覆盖与射程外盲区

- **射程内、全部命中**（对应表A 召回列的满分项）：去空格强特征（C01）、弱特征组合（C02）、
  未渲染占位符与运行时标签（C04/C05）、全局兜底与自相矛盾并存（C06/C09）、否定语境与引用剥离
  （C11/C12）、跨行撇号不吞抑制句（C13）、重复开标签与孤儿闭标签（C22/C23）、
  英文段名/裸冒号段头/全角括号/圈号编号（C17/C19/C20/C21）、12 条超载（C15）、
  too_short 边界 99（C28）。
- **刻意放行的边界**（负例，表A 零 FP 的出处）：弱特征单串（C03）、恰好 8 条（C16）、
  交付物清单段（C18）、逐字段豁免/空输入分支/反向规则（C08/C10/C07）、散文引用（C24）、
  too_short 边界 100（C29）。
- **已知漏判（计 FN）**：C14（同行撇号吞句）。
- **已知误报形态（计 FP）**：C25（最小复现）+ R38 + R42（真实交付物）。
- **射程外（不计分，规则 docstring 声明不做语义猜测）**：HTML 注释形式的过程标记
  （`<!-- fake reviser -->`，C26；真实文本 R05–R07 同型）、邀请编造数据的措辞
  （「数据不够你自己合理判断」，C27；真实文本 R16 同型）、抑制句的换说法
  （如「直接忽略本次请求」，不在触发词表内）。

## 六、标注协议与诚实边界

- 标注由本轮作者完成，**非盲标**（读过实现与全部注释）⇒ 读数是「实现与标注合同的自洽性」，
  **不是外部效度**；对抗负例是构造时就知道该放行的，表B 的「仅真实」列才是误报率的诚实分母。
- 真实文本全量收录、无一挑选；12 条命中文本的逐条判定（含两例误报）理由见语料 JSON 的
  `labels` 与本文第四节。
- 规则判据全部确定性：同语料同实现下读数可精确复算；实现或语料一变，守卫测试会红。
- **本轮只测量、不修规则**：第四节 1/2 的修复各需独立轮次（行为变更 + 变异验证），
  提前修会让本表的基线读数失锚。
