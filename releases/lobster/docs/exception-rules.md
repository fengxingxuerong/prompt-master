# 异常处理规则文档（缺货 / 断供 / 死虾 / 退款）

> 版本 1.0（演示口径）· 台账页同步展示 · 真实运营前需与实际履约能力对齐

## 1. 缺货 / 断供

**触发**：客户下单并确认后，批次库存不足。
**规则**：
1. 第一时间（≤2 小时）通知客户，状态置 `out_of_stock`；
2. 客户二选一：
   - 全额原路退款（1 个工作日内）；
   - 免费改期至最近到货批次，并赠 5% 加量；
3. 台账记录：缺货规格、数量、客户最终选择。
**不出现的情况**：静默取消、超时未通知。

## 2. 死虾 / 活力不达标

**触发**：签收时龙虾无活力（触须无反应、肢体松软）。
**规则**：
1. 客户 30 分钟内拍摄视频：未开箱整体 + 开箱特写，联系客服；
2. 判定属实 → 当日补发同规格 1 只 或 全额退款，运费我方承担；
3. 超时（>30 分钟）或已烹饪 → 不予赔付（鲜活冷链的时效特性，下单页已明示）。
**台账记录**：订单号、客户举证时间、判定结果、赔付方式。

## 3. 退款

| 时机 | 规则 |
|---|---|
| 发货前 | 无条件全额退款，1–3 个工作日原路返回 |
| 发货后，客户原因拒收 | 扣除冷链运费后退款 |
| 发货后，我方原因（断冷/延误/死虾） | 全额退款 + 运费承担 |

**台账记录**：退款原因、金额、发起时间、完成时间。

## 4. 状态机（台账 status 字段）

```
pending（待确认）
  → confirmed（已确认）
    → shipped（冷链在途）
      → delivered（已签收）
任一发货前状态 → out_of_stock / refunded
shipped 后 → dead_compensation / refunded
```

## 5. 演示边界声明

- 本文档为 demo 口径：所有赔付与时效规则需在真实运营前与资金、法务、履约方确认；
- 演示环境不产生真实退款，仅台账状态流转与 history 记录。
